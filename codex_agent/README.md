# GDAC Social Media Analytics Pipeline

This repository contains a modular, year-agnostic data pipeline for Super Bowl social
media analysis. It ingests raw data, cleans and enriches records, computes KPIs,
produces EDA/NLP outputs, and generates reporting artifacts.

## Architecture At A Glance

- Orchestrator-driven pipeline: `src/orchestrator/run_pipeline.py`
- Stage modules: ingestion, cleaning, enrichment, analysis, visualization, reporting
- Chunked CSV support for GB-scale inputs
- Dual NLP tracks on every run:
  - Lexicon NLP (`nlp_lexicon`)
  - ML NLP (`nlp_ml`, with automatic fallback if ML libs unavailable)

## Repository Map (What Each Subdirectory Contains)

### Top-level

- `config/`: Runtime configuration (`pipeline.yaml`, event windows, keywords, KPI defs).
- `data/`: Runtime data lake partitions.
  - `data/raw/`: Raw source input files by event/year.
  - `data/cleaned/`: Cleaned JSONL stage outputs.
  - `data/processed/`: Enriched JSONL stage outputs.
- `outputs/`: Final artifacts by event/year + cross-year files.
- `scripts/`: Utility scripts (for example `run_smoke_pipeline.sh`).
- `specs/`: Planning/spec artifacts generated by speckit workflow.
- `src/`: Pipeline source code.
- `tests/`: Unit, integration, regression, and contract tests.
- `.specify/`: Template/memory automation for plan/spec/task governance.

### `src/` modules

- `src/orchestrator/`: Pipeline orchestration, CLI parsing, manifests, artifact index.
- `src/ingestion/`: Input readers (JSONL/CSV/CSV.GZ), chunk iteration, column mapping.
- `src/cleaning/`: Validation and normalization logic.
- `src/enrichment/`: Enrichment stage (minimal/no-op compatible with modular boundaries).
- `src/analysis/`: KPIs, hashtag/mention frequencies, NLP, brand analytics, YOY logic.
- `src/visualization/`: Chart/infographic-ready exports.
- `src/reporting/`: Narrative summaries, traceability, templates.
- `src/common/`: Shared schemas, IO helpers, and structured logging.

### `tests/` suites

- `tests/unit/`: Core logic tests for schemas/utilities/NLP/brand analytics.
- `tests/integration/`: End-to-end run behavior on toy inputs.
- `tests/regression/`: Determinism and output consistency checks.
- `tests/contract/`: Contract/schema checks against defined interfaces.

## Input Expectations

Place source files under:

- `data/raw/<event>/<year>/posts.csv` (or `.csv.gz`, or JSONL)

Current CSV mapping in `config/pipeline.yaml` expects:

- IDs/text/time: `id`, `text`, `created_at`
- Ad/brand: `brand_ad_name`
- Engagement: `public_metrics.retweet_count`, `public_metrics.like_count`,
  `public_metrics.reply_count`, `public_metrics.quote_count`
- Entities: `entities.hashtags`, `entities.mentions`

`year` is derived from configured year column (for example `created_at` date string).

## Key Outputs

For each year (`outputs/super-bowl/<year>/`):

- `manifests/run_manifest.json`: run metadata + config hash.
- `manifests/artifact_index.json`: all generated artifacts + checksums.
- `manifests/run.log.jsonl`: structured run logs.
- `manifests/timing_profile.json`: stage runtime profile.

- `kpis/kpis.json`: baseline KPI metrics.
- `kpis/hashtag_frequencies.jsonl`: hashtag frequencies.
- `kpis/mention_frequencies.jsonl`: frequently tagged accounts.
- `kpis/brand_popularity.jsonl`: top brands by retweets/likes/total interactions
  (with typo grouping).
- `kpis/roi_join_ready.csv`: ad+emotion table for ROI join (lexicon + ML side-by-side).

- `kpis/nlp_lexicon/*`: lexicon NLP outputs.
- `kpis/nlp_ml/*`: ML NLP outputs (or fallback mode output).

- `visuals/*`: visualization-ready assets.
- `summaries/*`: yearly, white paper, executive summaries + traceability.

Cross-year:

- `outputs/super-bowl/year_over_year.json`

## Commands

### 1) Install dependencies

Base:

```bash
python3 -m pip install -e .
```

Enable ML NLP path (`torch` + `nltk`):

```bash
python3 -m pip install -e '.[ml]'
```

### 2) Run full pipeline

Single year:

```bash
python3 -m src.orchestrator.run_pipeline --event super-bowl --year 2025 --config config/pipeline.yaml
```

Multi-year:

```bash
python3 -m src.orchestrator.run_pipeline --event super-bowl --years 2023,2024,2025 --config config/pipeline.yaml
```

### 3) Run smoke script

```bash
./scripts/run_smoke_pipeline.sh
```

### 4) Run tests

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

### 5) Run parts of pipeline (module-level)

Quick interactive checks:

```bash
python3 - << 'PY'
from src.ingestion.ingest_x_data import iter_chunks
for i, chunk in enumerate(iter_chunks(raw_root='data/raw', event_name='super-bowl', year=2025, input_format='csv', chunk_size=1000), start=1):
    print('chunk', i, 'rows', len(chunk))
    if i == 1:
        print('sample', chunk[0])
        break
PY
```

```bash
python3 - << 'PY'
from src.analysis.brand_analytics import BrandAggregator
rows = [{'brand_ad_name':'Pop Corners','retweet_count':'10','like_count':'20','reply_count':'1','quote_count':'1'}]
a = BrandAggregator()
a.update(rows)
print(a.finalize())
PY
```

## Performance / Long-Run Controls

Tune these in `config/pipeline.yaml`:

- `chunk_size`
- `progress_every_chunks`
- `progress_every_rows`
- `eda_top_n`
- `brand_top_n`
- `nlp_min_training_rows`

Check bottlenecks in:

- `outputs/<event>/<year>/manifests/timing_profile.json`
